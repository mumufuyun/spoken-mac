# 自定义模式与模型接入

## 创建模式

打开设置 → 模式 → 添加模式，填写名称和场景规则后保存。也可以复制现有自定义模式，再调整规则。最多添加六个自定义模式；删除后可重新添加。

- **场景规则**：定义当前模式完成什么任务，以及语气、结构和输出要求。无需填写 `{text}`。

例如，问答模式可以写：“回答语音中的问题，先给结论，再列出必要建议；信息不足时说明，不编造事实。”翻译模式可以写：“把语音翻译成简洁自然的英文邮件，保留原意，不添加未提及的承诺。”

六个预设继续用于整理原话，其中 AI 指令只整理发给另一个 AI 的指令，不回答或执行任务。自定义模式可以直接回答或生成文本，但不执行外部操作。菜单栏明确指定的输出语言优先于预设场景中的语言要求。自定义模式按你编写的场景规则执行：不叠加内置基础规则，菜单栏的输出语言也不会注入，语言要求可以直接写进场景规则；个人背景设置继续生效；所有模式统一附加最终回复约束（仅要求模型不把内部推理、接口元数据混入正文）。

内置提示词（全局基础规则和六个预设的场景规则）由产品内置，不在界面展示，也不可查看或编辑；界面只展示每个预设的一句用途说明。只有自定义模式的场景规则可以编写和修改。

## 切换与保存

菜单栏按预设和自定义分组展示模式。录音浮窗也能展开同一套网格：录音时可切换，停止时锁定本次模式、Prompt、语言、个人背景和模型连接。之后修改设置只影响后续录音。

设置页的修改先保留为草稿，保存后生效；切换页面、选择其他编辑项或关闭窗口时，未保存内容会提示保存或放弃。删除正在使用的自定义模式会切回流畅转写。

## 填写个人背景

设置 → 个人背景提供四类选填项。先填容易识别错的词，再按需要补充，每项一两句即可。

| 填写项 | 写什么 | 示例 |
| --- | --- | --- |
| 常用术语 | 正确名称、常见误识别和必要的含义 | Spoken 是语音输入工具，常被识别成“斯波肯”；API 保留大写。 |
| 工作或专业领域 | 从事的领域、常做的事 | 做软件产品设计，经常讨论用户访谈和交互。 |
| 沟通对象与用途 | 通常给谁看、用来做什么 | 给项目同事发进度消息，整理内部说明。 |
| 表达偏好 | 具体的句式、格式习惯和要避免的表达 | 用短句，多个事项分点，保留术语，不加客套结尾。 |

无需填写完整履历。原有自由文本完整保留在“其他补充”，可继续使用或自行分类；示例不会自动填入背景。保存后用于后续录音，清空也需保存才生效。

背景保存在本机；开启并保存后，仅在需要 AI 处理时发送给当前模型服务商。关闭会保留内容，后续请求不再使用。背景只辅助术语消歧和表达适配，本次明确要求与所选模式优先，不能据此补写事实或删减实质信息。

## 添加模型连接

在 AI 模型页添加连接，选择供应商、模型，填入自己的 API Key 后保存。已知供应商预填地址和常用模型，地址在高级设置中可编辑。同一家供应商可以保存多个连接，所有模式使用当前选定的一个连接。

| 供应商 | 新建连接默认模型 | 接入方式 |
| --- | --- | --- |
| MiniMax | MiniMax-M3 | 普通 API / Token Plan 订阅 |
| DeepSeek | deepseek-v4-flash | 普通 API |
| 智谱 | glm-4.7-flash | 普通 API |
| Kimi | kimi-k2.6 | 普通 API |
| 千问 | qwen3.8-flash | 普通 API |
| 自定义 | 自行填写 | OpenAI Chat Completions 兼容接口 |

MiniMax Token Plan 和普通 API 分别保存密钥；切换接入方式或供应商时重新填写对应密钥。智谱、千问 Coding Plan 有工具范围限制；Kimi Code 的产品集成范围也未明确覆盖 Spoken，首版只提供其普通 API 预设。模型和套餐范围以厂商说明为准：[MiniMax](https://platform.minimaxi.com/docs/token-plan/intro)、[智谱](https://docs.bigmodel.cn/cn/coding-plan/usage-notes)、[千问](https://help.aliyun.com/zh/model-studio/coding-plan)、[Kimi](https://www.kimi.com/code/docs/en/)。

自定义连接接受 Base URL 或完整 `/chat/completions` 地址。远程接口使用 HTTPS；本机 localhost、127.0.0.1 和 ::1 服务可使用 HTTP。未知模型使用供应商默认参数，不假定支持思考开关。

“测试连接”仅在点击时发送固定短文本，显示结果和耗时，会产生少量调用用量。不包含语音或个人背景，也不会保存未提交的配置。

## 2.1 升级与本地数据

首次启动先完整备份旧 Prompt，再统一启用新的基础规则和场景规则。旧版修改不自动拼入新规则；备份只保留在本地配置文件中，不再提供界面查看。备份或迁移失败时，原数据保留，设置页提供重试入口。

配置位于 `~/Library/Application Support/Spoken/Configuration/`：

- `modes-v2.json`：基础规则、模式和当前选择。提示词迭代会提升配置版本（当前为 4）：与旧默认值逐字一致（即从未编辑过）的基础规则和内置场景规则自动替换为新版，用户修改过的内容原样保留；低版本配置逐级迁移，迁移写入失败时原文件不变，下次启动重试。
- `legacy-prompts-v1.json`：升级前的完整 Prompt 和原有覆盖值，只生成一次。
- `model-connections-v1.json`：连接参数、当前连接和钥匙串引用，不包含密钥正文。

已有模型、URL和思考偏好保留。旧版共用密钥只迁移给升级时正在使用的连接，其他连接需分别配置。密钥仅保存在 Keychain；保存新连接配置失败时，原配置和密钥继续有效。删除当前模型连接后不自动切到其他厂商。

## 验证边界

离线回归通过模拟钥匙串和 HTTP 检查迁移、保存回滚、模式切换、请求参数与错误回退。原生界面快照覆盖浅色、深色和最小窗口，只使用合成内容。这些检查不代替真实麦克风、跨应用粘贴、VoiceOver和各厂商账户的实际验收。
