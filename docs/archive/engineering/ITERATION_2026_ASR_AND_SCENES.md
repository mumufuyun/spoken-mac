# 2026 云端 ASR 与使用场景迭代

## 目标

1. 消除长时间闲置、系统睡眠和网络波动后必须重启应用才能恢复云端识别的问题。
2. 将“AI 做什么”改为“文字最终用在哪里”，让后处理更符合真实输入场景。
3. 建立本地可观测指标和自动化回归测试，支持后续真实使用验证。

## 云端识别设计

每次录音创建独立逻辑会话，不复用长时间闲置的 WebSocket：

```text
开始录音 → 本地缓存 PCM → 建立 WebSocket → session.created
→ 发送缓存及实时音频 → 停止采集 → commit
→ 等待 completed/超时使用最后 partial → 有序关闭
```

关键保证：

- 所有 Provider 状态在单一串行队列上修改。
- 每次会话及每个 WebSocket task 都隔离，旧 task 回调不能污染新连接。
- 建连或传输失败最多自动重试两次，并重放当前录音缓存。
- 最多保留 64 MiB PCM 用于重放，超限时淘汰最早音频。
- `finish` 等待最终结果或 8 秒超时，不再 commit 后立即断开。
- 云端彻底失败时，自动模式切换本地识别；纯云端模式显示明确错误。
- 睡眠/唤醒通知使用 `NSWorkspace.shared.notificationCenter`。

## 使用场景

一级场景：

- 原样转写
- 日常聊天
- 工作沟通
- 正式材料
- 会议记录
- 内容分享
- AI 指令

翻译不再是一级模式，而是可与任意场景组合的输出语言选项。

旧版设置自动迁移：直接输入/翻译迁移为原样转写，润色迁移为日常聊天，
摘要/格式化迁移为会议记录，Prompt 迁移为工作沟通。

## 隐私与验证

稳定性指标仅保存在 `UserDefaults`，包括会话、成功、失败、重连和本地降级次数，
不采集音频及转录正文。

自动化测试覆盖：

- 音频重放缓存顺序和容量淘汰。
- 最终结果与 partial 超时兜底。
- 七个场景完整性及默认 Prompt 约束。
- 旧配置迁移。
- 基于目标应用的场景建议。

真实环境仍需执行睡眠唤醒、断网恢复、短语音和百次连续录音测试。
