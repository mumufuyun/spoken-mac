# Spoken 全流程延迟优化记录

> 日期：2026-08-25
> 范围：ASR首字、ASR收尾、AI后处理、文本写入；不实施AI流式返回

## 已实施

1. 全流程耗时埋点
   - 记录热键、浮窗、录音、首帧音频、ASR连接、首个识别文本、停止、ASR Final、AI请求、AI完成和写入。
   - 不记录音频、转录文本或模型输出。
   - 每项保留最近50次样本，计算P50、P90、P95。
   - 设置页“语音－稳定性记录”可查看首字、ASR收尾、AI处理和结束到写入的分位数。

2. 有边界的ASR预连接
   - 应用启动后、每次识别完成后提前建立WebSocket。
   - 预连接TTL为180秒；API Key、模型、连接状态或心跳不匹配时禁止复用。
   - 睡眠、唤醒、应用退出和网络路径变化时失效并按需重建。
   - 录音中的网络变化仍交给现有重连与音频重放机制，避免主动断开正在使用的会话。

3. 录音启动路径
   - 移除浮窗后的固定150ms等待。
   - 移除音频引擎重置100ms和启动后200ms的阻塞等待。
   - 音频Buffer由4096帧降至2048帧，16kHz下理论粒度由约256ms降至约128ms。
   - 正常冷启动减少约450ms固定等待；首帧粒度再减少约128ms。

4. DeepSeek V4 Flash AI后处理
   - 百炼上的`deepseek-v4-*`请求显式设置`enable_thinking=false`。
   - 根据原始转录长度设置有界`max_tokens`，范围256—16384，避免短文本无界生成，同时保护长转录不被低上限截断。
   - 加强工作沟通、正式材料、会议记录、内容分享和AI指令的长度适配要求，补偿关闭思考后可能出现的处理过度克制。

5. 文本写入
   - 删除固定800ms等待。
   - 改为检查目标应用是否已处于前台：已就绪立即写入，否则每50ms检查一次，最多等待800ms。

## AI A/B结果

使用`deepseek-v4-flash-0731`、同一组18条短／中／长场景样本：

| 配置 | 结果 |
|---|---|
| 关闭思考，Prompt强化前 | 18/18成功；平均3.78秒，中位数4秒，最长8秒 |
| 开启思考并使用相同合理输出上限 | 10/18得到完整正文；平均7.67秒，中位数8秒，最长12秒；推理Token挤占正文空间 |
| 关闭思考，Prompt强化后首次全量 | 17/18成功；成功请求平均3.88秒，中位数4秒，最长6秒；1次服务端连接30秒超时 |
| 会议场景单独复测 | 3/3成功；平均4.33秒；短、中、长文本均正确区分结论、待办和待确认项 |

关闭思考后，数字、负责人、时间、条件、不确定性、AI指令不误执行等高风险边界均保留。最终Prompt恢复了长工作消息分段、正式材料书面化、内容分享分段和会议分类能力。

服务端仍存在偶发长尾：一次关闭思考的会议中文本请求耗时21秒，另一次连接超过30秒。应用继续保留20秒超时并回退原文，避免无限等待。
