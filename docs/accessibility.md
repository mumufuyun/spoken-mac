# 辅助功能授权与提醒

辅助功能允许 Spoken 发送粘贴操作，把结果填入用户正在使用的输入框。麦克风授权只允许录音，不能替代辅助功能授权。

## 首次设置

1. 将 Spoken 放在固定位置（建议“应用程序”文件夹），从该位置启动。
2. 在引导中点击“打开辅助功能设置”，进入“系统设置 → 隐私与安全性 → 辅助功能”。
3. 找到 Spoken 并打开开关；如果列表中没有它，点击“+”添加当前运行的应用。引导中的“在 Finder 中显示当前应用”可以定位实际文件。
4. 回到 Spoken，确认“辅助功能已授权”；也可点击“重新检测”。

点击授权入口或“重新检测”不会被视为授权成功。状态来自 macOS 的辅助功能信任检查和事件发送权限检查；仅辅助功能信任通过、事件发送权限仍未生效时，显示“自动输入权限尚未生效”。

系统设置路径及“+”添加应用的操作依据 [Apple 隐私与安全性设置说明](https://support.apple.com/zh-cn/guide/mac-help/mchl211c911f/mac)。

## 跳过后的提醒

- 首次缺少权限时显示独立引导，窗口展示不抢走输入焦点。选择“稍后设置”或关闭后，不会每次启动重复弹出完整引导。
- 菜单栏图标持续显示警示，模式面板保留授权入口；“设置 → 权限与授权”始终可用。
- 录音浮窗显示“需手动粘贴”。不阻止录音、转录及 AI 处理。
- 输出时再次检查权限。未生效则保留结果在剪贴板，展示 10 秒提示：“文字已复制……请回到输入框按 ⌘V 粘贴”，并提供授权入口。每次未自动输入的结果都有反馈；提示不混入正文、不抢焦点、不阻挡下一次录音。
- 快捷键冲突警示和权限警示可以同时出现；缺少权限时暂不显示普通快捷键操作引导，避免暗示自动输入已准备好。

切换应用、从系统设置返回、系统唤醒、打开模式面板、开始录音和输出前均重新检测。授权页面可见期间每 2 秒检测；点击系统设置入口后额外跟踪 2 分钟。权限生效后清除持续警示，后续撤销权限时恢复提醒。没有后台权限请求或自动更改系统设置。

## 更新应用后仍无法自动输入

更新或替换 Spoken 后，系统设置可能仍保留旧条目，且开关显示为开启，但授权未对新版生效。仅关闭再打开开关可能无效。麦克风可用、密钥已保留，也不代表辅助功能已生效。

若 Spoken 仍提示未授权或未生效：

1. 在“系统设置 → 隐私与安全性 → 辅助功能”中选中旧的 Spoken，点击“−”移除。
2. 点击“+”，重新添加“应用程序”里的新版 Spoken.app，并开启开关。若装在其他位置，用 Spoken 引导中的“在 Finder 中显示当前应用”定位。
3. 回到 Spoken“权限与授权”点击“重新检测”。仍未生效或系统要求时，退出并重新打开 Spoken。

以 Spoken 内的检测结果为准，不要只看系统设置中的开关；恢复后在输入框试一次自动输入。已经正常生效时，无需删除重加。未恢复前，看到“文字已复制”后可按 `⌘V` 手动粘贴。

当前本地签名版本可能遇到此问题，不代表每次更新都必然发生。应用不会自动重置授权、改动其他应用的权限或替用户开启开关。

已授权不等于每个输入框都能接收文字。请确认目标应用仍在前台，光标位于可编辑区域。Spoken 只能确认已发送粘贴事件，不能通用地确认目标应用已插入文字。

### 开发说明

2026-10-03 检查：本机安装的 2.4.7 为 ad-hoc 签名，未设置 Team Identifier；其 designated requirement 绑定当前构建的 `cdhash`。与本地备份 2.3.0 比较，哈希不同，2.4.7 无法通过旧版签名要求检查。这支持“更新导致旧授权不再匹配”的判断，与用户报告的删除重加后恢复一致；本次未重置系统权限，也未独立复现每次更新的完整过程。

长期应使用稳定的 Developer ID Application 签名身份，并验证连续升级时的权限延续；公证用于分发信任，不能代替稳定签名身份。首次从临时签名迁移到正式签名时仍需验证重新授权行为。签名身份与版本连续性的依据见 [Apple Code Signing Guide](https://developer.apple.com/library/archive/documentation/Security/Conceptual/CodeSigningGuide/AboutCS/AboutCS.html)；Apple DTS 也说明 [ad-hoc 签名会导致 TCC 权限问题](https://developer.apple.com/forums/thread/125438)。

## 文本保留与故障反馈

未授权时不再尝试系统脚本粘贴，避免另一路自动化授权提示。未授权、目标失焦或粘贴事件创建失败时，剪贴板保留本次结果，不恢复旧内容；剪贴板写入失败不会显示“已复制”，会保留内存中的结果并提供“重试复制”，直到用户关闭提示或开始下一次录音。

权限状态、提示正文与识别结果分离；不记录用户输入内容。仅在成功发送粘贴事件后恢复先前剪贴板，并检查剪贴板是否被用户修改以及是否仍属于该次请求。
