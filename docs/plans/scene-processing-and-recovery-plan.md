# Spoken 场景化处理与找回改造计划

日期：2026-10-02。范围：当时的 macOS 项目。

归档说明（2026-10-03）：本文保留最初方案。当前已实现范围见[找回输入](../input-recovery.md)和[AI 后处理](../ai-postprocessing.md)；下文的分阶段处理、编辑原文等建议不代表已交付。

本计划将两项能力放在同一条处理流程中：根据场景和文本特征选择整理方式；当结果不满意或交付失败时，找回转录原文并重新整理。首版优先提供最近一次输入的恢复能力，再用现有测试集逐场景验证并启用自动处理策略。

方案撰写时的交付边界：固定词表及替换循环已从源码删除，字母间空格合并保留。本文中的场景化处理、找回界面和数据结构均为改造方案，尚未实施；本次没有安装或发布新版应用。

## 1 目标与首版范围

用户应能完成三件事：普通输入保持当前便捷程度；长而复杂的内容得到适合该场景的整理；对不满意的结果重新处理，无需重新录音。

| 项目 | 首版建议 |
| --- | --- |
| 场景选择 | 保留用户手动选择的模式，不根据文本擅自切换场景 |
| 处理方式 | 提供自动、快速、深入三个选项；内部支持直接输出、单次处理和分阶段处理 |
| 自动策略 | 按场景、文本长度和模型能力选择；未通过评测的组合继续使用现有流程 |
| 优先试验场景 | AI 指令、会议记录；随后验证内容分享 |
| 找回范围 | 最近一次非空转录，原文及有限个处理版本，保存在内存中 |
| 找回操作 | 复制原文、复制结果、编辑后整理、重新整理、深入整理、清除 |
| 输出交付 | 正常录音保持现有自动粘贴；找回后的结果先展示，由用户复制使用 |
| 首版之外 | 跨重启历史、音频回放、云同步、自动换模型、自动采集其他应用内容、通用多 Agent 框架 |

“深入”表示使用当前场景经过验证的更充分处理方式，不承诺一定更好。它可能对应一次思考请求，也可能对应分阶段整理。界面不要求用户理解内部步骤。

## 2 当前实现与改造入口

| 当前事实 | 改造含义 |
| --- | --- |
| 七个内置场景和自定义模式主要通过规则区分，AI 入口返回一份正文 | 增加统一的处理计划和流程执行器，保留现有请求服务作为底层能力 |
| 停止录音时冻结场景、语言、规则和模型配置 | 冻结用户选择后，等待最终转录，再依据文本生成本次处理计划 |
| 内置场景按字数调整等待时间和输出预算，当前最长 60 秒；适配器当前统一限制最多 16,384 输出 tokens | 新策略需同时管理上下文、正文、思考和总等待预算，不能仅翻转思考开关 |
| 自定义模式有独立预算，可能用于问答和创作 | 不套用“所有输出都必须来自原文”的会议或整理流程 |
| 输出检查覆盖正文解析、思考内容和协议字段过滤、截断及粘贴前复查 | 继续保留；新增中间产物检查，不将中间 JSON 或思考内容当成最终正文 |
| 识别链路目前在多个位置调用格式处理 | 找回原文必须在这些处理之前保存真实识别文本，不能从最后输出反推 |
| 请求服务只管理一个活动请求，耗时记录也只有一个活动链路 | 首版串行执行一个 AI 任务，避免录音和重处理抢占状态、串写结果 |
| 现有真实模型评测脚本另行拼接提示词和解析结果 | 改为调用应用共用的处理入口，沿用已有测试集 |

## 3 统一处理流程

正常输入按以下顺序执行：

1. 停止录音，冻结用户选择的场景、输出语言、处理偏好和配置。
2. 取得本次识别结束后选定的非空转录，保存未经过词语或格式修改的原文。
3. 从原文生成用于处理的文本副本；现有字母空格合并只作用于副本。
4. 判断是否需要 AI，再按场景、文本长度、用户偏好和已验证模型能力生成处理计划。
5. 执行计划；每阶段共享同一总截止和取消状态。
6. 验证最终正文，保存结果与状态；正常录音走现有交付方式。
7. 用户打开找回窗口后，可从原文或明确编辑过的原文创建新的处理尝试。

原始转录、实际处理输入和每次输出分别保存。任何重新处理都不默认以上一版整理结果作为输入，避免已有遗漏和误改累积。

同一次录音对应一个输入记录；一次重新整理对应一个新的处理尝试；一次网络重试只属于当前尝试。三者使用不同标识。

## 4 场景与文本共同决定处理策略

### 4.1 用户选择与内部策略

| 用户选项 | 运行行为 |
| --- | --- |
| 自动 | 使用已通过评测的场景和长度规则；未覆盖的情况回到当前单次处理 |
| 快速 | 一次处理，在模型允许的情况下关闭思考；始终思考的模型明确显示其能力限制 |
| 深入 | 使用该场景已验证的深入策略；保持当前模型，不自动切换供应商 |

原样转写且输出语言为原语言时，直接输出，不因长度或深入选项调用 AI。原样转写加翻译时，只做翻译；深入选项不能把它变成摘要或润色。

首版在设置中提供统一处理偏好，模式对应的具体流程由内部策略表管理，不给每个场景堆叠额外开关。找回窗口允许只对本次尝试选择处理方式。

升级时保留原有行为：原思考关闭迁移为快速，原思考开启迁移为深入，并保持已有有效参数。对自定义模式和未支持的模型，深入仍可沿用原单次请求配置，不强行启用分阶段处理。只有评测通过后，新安装才默认自动；已有用户可主动选择自动。

### 4.2 文本长度与复杂度

定义每个场景的候选阈值 `L_scene` 和 `X_scene`，分别用于长文本和超长文本。具体数值通过现有测试集的实际长度、错误类型和耗时确定，计划阶段不预设通用的 1,000 字或 3,000 字标准。

首版使用字数判断处理强度，使用模型对应的 token 估计控制容量。两者职责不同：长度阈值决定是否值得深入整理；上下文与输出限制决定能否完整处理。英文、中文和混合文本不能直接按相同字数等同 token 数。

重复回绕、自我修正、多主题、分散约束可作为后续辅助信号。首版不为判断复杂度额外调用一次模型，也不单凭几个关键词改变用户场景。若现有样本不足以确定某个阈值，该组合先只开放手动深入，不启用自动切换。

### 4.3 候选场景策略

下表是待评测的实现候选，不代表已确认收益。完整输入能在预算内处理时，优先保留原文进入请求。

| 场景 | 普通文本 | 长且复杂的文本 | 首要检查 |
| --- | --- | --- | --- |
| 原样转写 | 直接输出或按用户语言选择翻译 | 保持同一用途 | 不改写、不摘要 |
| 日常聊天 | 单次清理口语 | 单次归并重复并轻量分段，默认不分阶段 | 本人语气和实质信息 |
| 工作沟通 | 单次整理 | 比较单次快速与单次思考效果，优先保持一次请求 | 诉求、分工、时间、条件 |
| 正式材料 | 单次书面化 | 先梳理事实和层次，再组织正文 | 不新增论据、结论或承诺 |
| 会议记录 | 单次分类 | 先提取议题和事项状态，再归并、成文 | 建议、决定、待办、分歧的边界 |
| 内容分享 | 单次调整表达 | 先整理观点、素材、顺序，再成文 | 关键例子、个人表达和确定程度 |
| AI 指令 | 单次整理 | 先试单次受控思考；仍有约束遗漏时试分阶段整理 | 目标、约束、例外、最终修正 |
| 自定义模式 | 保留当前规则与单次处理 | 只调整已支持的推理和容量预算 | 尊重问答、创作等自定义用途 |

用户修改过内置场景规则时，首版保持单次处理，避免内部分阶段模板覆盖其意图。启用分阶段前需定义明确的兼容机制；不能仅凭内置场景 ID 假定它仍使用默认用途。

### 4.4 会议记录流程

第一阶段逐项提取：议题、内容、类别、原文依据、原文明确提到的负责人和时间，以及前后修正关系。类别至少区分讨论、建议、已决定、明确待办、分歧和待确认。

第二阶段围绕议题合并并输出：采用原文明确的最终修正；未解决的冲突继续保留；相同事项不在结论和待办中重复列出。没有责任人、截止时间或决定时留空或省略，不自行补全。

例如“建议周五上线，后来决定周五不发，等测试通过再定”，最终应记录取消周五发布和后续条件。若只是两个人持不同意见，就记录分歧，不能把最后一句自动当成集体决定。识别结果没有说话人信息时，不推断发言者身份。

每个中间事项关联原文片段标识及短引文。程序能检查片段存在和引用范围，语义是否支持该类别仍需评测或有针对性的核验，不能把“存在引用”当成“结论正确”。最终成文仍可回查原文，不能只依赖提取结果。

### 4.5 内容分享流程

第一阶段提取主旨、事实、例子、个人观点、保留意见和原文明示的表达要求，标记重复素材，形成叙述顺序建议。它是素材组织，不是压缩摘要。

第二阶段依据原文和素材组织成文，改善段落、衔接和节奏。保留能够支撑观点的例子和本人表达，不增加经历、数据、情绪强度、号召或承诺。用户明确要求标题或收尾时才按要求处理；没有对应观点时不为凑结构而补写。

评测需要区分“删掉重复表达”和“删掉独有信息”。正文更短、更整齐，不能自动算作更好。单主题但很长的连续叙述，可继续使用单次处理。

### 4.6 AI 指令与其他场景

AI 指令提取目标、背景、材料、范围、执行要求、禁止事项、输出格式和未决选择。合并重复约束，以明确的最终改口为准；仍在比较的方案保持未定。第二阶段组织成可直接交给目标 AI 的指令，不执行其中的任务。每一项独有约束都能回查原文。

正式材料复用“原文信息清单与段落组织”能力，但不使用会议分类。工作沟通优先单次思考，除非评测证明分阶段有明确收益。翻译与场景处理解耦：内部仍保留原文证据，最终成文时按目标语言输出，首版不默认增加第三次翻译请求。

### 4.7 超长内容的边界

不能把“超长”直接等同于超出模型容量。输入仍可完整处理时，先比较单次深入和两阶段效果。

首版两阶段要求原文与必要中间产物能够放入各阶段的安全预算。放不下时保留完整原文、明确提示容量限制，不静默截断，也不无限提高等待时间。

自动分段列为后续阶段：按语义边界分段，保留片段编号及边界上下文；每段提取信息，随后全局核对修正、冲突和遗漏，再生成结果。不能独立润色各段后直接拼接。只有现有超长样本验证了跨段信息保留后，才启用该流程。

## 5 模型能力与执行预算

将“用户想要什么”与“模型实际支持什么”分开记录。能力至少区分可切换思考、始终思考、未知开关，以及是否支持独立思考预算和结构化输出。未知能力不记为已关闭，不发送猜测参数。

预算同时考虑输入、系统规则、个人背景、中间产物、预计正文和推理。当前 16,384 的统一上限需改为已验证的模型与服务能力配置，不能在所有连接上简单放大。正文长度按场景估计，推理预算按供应商语义设置。

| 内部流程 | 调用数量与限制 | 等待策略 |
| --- | --- | --- |
| 直接输出 | 0 次 AI 调用 | 识别完成后走交付 |
| 单次快速 | 1 次，最多 1 次可恢复网络错误重试 | 首版沿用当前 20 至 60 秒长度策略 |
| 单次深入 | 1 次，最多 1 次可恢复网络错误重试 | 候选总上限 90 秒，须经长文本实测调整 |
| 两阶段处理 | 2 次，全流程合计最多 1 次可恢复网络错误重试 | 候选总上限 120 秒，第二阶段只能使用剩余预算 |

90 秒和 120 秒是试验预算，不是延迟承诺或已确认的上线配置。首版不默认增加模型自评调用或无限语义修复循环；结构解析失败作为明确失败处理。调用次数、等待时间和结果质量必须同时进入评测。

重试只针对经过分类的临时网络或服务错误；身份、参数错误不重复请求。总截止到达后取消在途阶段，不再继续提交后续请求。首版不引入流式粘贴，只有验证通过的完整正文才能交付。

模型参数实施时复核[百炼思考模式](https://help.aliyun.com/zh/model-studio/deep-thinking)和[输出参数](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)。不同接口对思考与正文额度的计算不同，不把同一预算语义泛化到全部模型。

## 6 找回的产品交互

### 6.1 入口与窗口

菜单栏面板增加“找回上次输入”。没有记录时显示“暂无可找回的输入”。正常录音结束不自动弹出窗口；原文回退或交付失败的提示可附带“查看上次输入”。

窗口包含转录原文和整理结果两个区域，长文可滚动查看。顶部显示时间、场景、输出语言和本次处理状态；模型及处理方式可放在次要信息中。使用键盘和 VoiceOver 能访问所有操作，深浅色均可读。

| 操作 | 行为 |
| --- | --- |
| 复制原文 | 复制未经过本地格式处理和 AI 改写的转录 |
| 复制结果 | 复制用户当前选中的完整结果；失败或无正文时不可用 |
| 编辑后整理 | 从原文建立可编辑副本，原文保持不变；用户保存后明确显示将使用编辑稿 |
| 重新整理 | 使用原文或用户已保存的编辑稿，按窗口中展示的场景、语言和处理方式执行 |
| 深入整理 | 对相同输入使用该场景可用的深入策略；不可用时说明原因，不伪装成已升级 |
| 恢复原文作为输入 | 丢弃编辑稿，后续尝试重新从原文开始；不删除已产生结果 |
| 清除 | 取消该记录正在进行的重处理并清除原文、编辑稿和结果；迟到响应不得恢复记录 |

场景和语言在窗口内可以修改，只影响新的尝试，不改变菜单栏当前选择。重新处理不会自动把上一版结果送给模型，也不自动覆盖其他应用中已经编辑过的文字。

首版只提供复制后手动粘贴，不提供“替换之前那段文字”。通用粘贴接口无法可靠确定原插入范围。复制不要求辅助功能权限。

### 6.2 保留规则

首版默认在内存中保留最近一次非空输入，设置中可关闭；界面说明“仅保留最近一次，退出后清除”。不保存音频，不写入日志、偏好文件或数据库，不增加任何后台正文上报。关闭保存时立即清除现有记录。

新录音开始时不清空旧记录。只有识别完成并取得非空转录后，才用新记录替换旧记录。空录音、启动失败或用户在录音阶段取消，不覆盖旧记录。

建议最多保留同一输入的 3 个处理尝试，包括首次处理；新增尝试时淘汰最旧尝试，保留原文和当前最新结果。失败尝试记录失败状态而非“成功的原文结果”。窗口显示版本时间和处理方式，不自动宣称最新版本最好。

内存正文总量建议上限为 4 MiB，以 UTF-8 字节计，作为可调整的实现上限。超出时先移除旧结果；若单份原文仍超限，本次不启用找回并明确提示，不能截断后标为完整。该策略不改变正常录音的已有输入能力。

退出、崩溃或系统结束进程后无法找回，这是内存方案的产品边界。若实际需求包含重启恢复，再独立设计本地持久化与清理期限；本次不把它隐含加入首版。

### 6.3 配置与模型变化

重新整理默认使用原记录关联的场景规则、语言及连接配置摘要。记录只保存连接标识、服务地址和模型等必要配置，不保存 API Key；发起新尝试时重新读取对应连接的当前有效密钥，运行期间使用临时快照。

如果原连接、模型或规则已修改，窗口展示差异并提供“使用当前配置重新整理”；用户点击后才采用新的配置。原连接已删除或缺少密钥时，引导选择可用连接，不静默切换到另一家服务。每次新尝试开始后，配置再次冻结。

原始记录内用于重现的提示词和相关背景仅随记录存在于内存，清除时一并释放。全局关闭个人背景后，新尝试不再沿用旧背景，界面显示配置已变化；不能为重现旧结果而绕过用户当前的数据使用选择。

## 7 数据结构与并发规则

建议新增以下职责明确的类型，具体名称可在实现时调整。

| 类型 | 主要内容 |
| --- | --- |
| `RecognitionResult` | 未格式化原文、可用处理副本、识别来源及 final 或 partial 状态 |
| `ProcessingPreference` | 自动、快速、深入；独立于供应商参数 |
| `ProcessingPlan` | 场景、策略版本、长度级别、阶段列表、实际思考状态、预算、选择原因 |
| `RecoveryRecord` | 输入 ID、时间、原文、编辑稿及修订号、原配置摘要、有限个尝试 |
| `ProcessingAttempt` | 尝试 ID、输入修订号、触发来源、冻结配置摘要、计划、输出、错误、耗时 |
| `IntermediateArtifact` | 场景对应的信息项及原文引用；仅供当前尝试处理 |

识别状态、处理状态和交付状态独立记录。取得 partial 后回退、AI 超时保留原文、发送粘贴事件等不能合并成一个“成功”。现有 `InjectionOutcome.inserted` 仅表示粘贴事件已发送，找回界面不能据此声称目标应用已确认收到。

一个尝试的状态为：待执行、处理中、成功、失败或取消。成功必须有通过检查的完整正文。两阶段的中间产物不是可复制的最终结果。

首版只允许一个 AI 尝试执行：

- 新录音优先。开始新录音时取消找回窗口中的活动尝试，但保留已保存的原文和旧结果。
- 正在录音或正常输入处理中，找回窗口可以查看和复制，重新处理按钮暂不可用。
- 用户连续点击重新整理时，取消上一尝试并分配新尝试 ID；旧响应只允许完成清理，不得更新窗口或触发粘贴。
- 关闭找回窗口取消其中正在运行的重处理，保留记录，避免隐藏任务继续消耗；正常录音流程不受窗口关闭影响。
- 新的非空识别替换记录时增加记录代次。所有回调同时核对输入 ID、尝试 ID 和记录代次，防止旧内容写入新记录。
- AI 处理中按 Esc 取消时，不自动粘贴；若已取得原文，原文仍可从找回入口访问。关闭保存时则不保留。

取消必须贯穿网络请求、阶段间切换、重试定时器、状态更新和交付。既有服务的单请求标识继续作为底层保护，但不能代替整个流程的尝试 ID。

## 8 工程拆分

| 模块 | 建议修改 |
| --- | --- |
| `SpeechService` | 统一结束时的转录结果对象，云端 final、partial 回退和本地 final 都保存未修改原文；避免提前格式化污染原文 |
| `SpeechPostProcessor` | 保持本次已删除词表的状态；将剩余格式处理限定于处理副本 |
| `RecordingViewModel` | 接收原文，建立输入记录，冻结设置，调用统一执行器；负责显示和交付，不负责策略判断 |
| 新增 `ProcessingPlanner` | 纯逻辑：输入场景、长度、偏好、能力及策略版本，输出处理计划，便于离线验证 |
| 新增 `ProcessingCoordinator` | 管理阶段、总预算、取消、重试及结果；正常输入和找回共用 |
| `AIProcessingService` | 保留请求、认证和网络解析；允许传入阶段参数及剩余时间，不再把所有步骤都当成最终正文请求 |
| `ModelRequestAdapter` | 增加实际思考能力、预算语义、结构化输出和容量配置；未知能力明确标识 |
| `PromptComposer` | 按场景和阶段组装规则，传递原文与中间素材，继续分离指令和转录内容 |
| 新增中间产物校验器 | 检查结构、来源范围、类别和字段；JSON 格式正确不代表内容真实 |
| `AIOutputGuard` | 原有最终正文保护继续生效，原始材料中的合法分析或代码不能误删 |
| 新增 `RecoveryStore` | 主线程可观察内存状态，管理保留上限、编辑修订、尝试版本和清除 |
| 菜单栏与新增找回窗口 | 提供入口、原文与结果展示、复制和重处理；不抢正常录音焦点 |
| 配置存储 | 增加处理偏好和找回开关，原子迁移并保留旧设置，不写入正文 |
| 耗时统计 | 区分正常输入和重处理；总耗时包含全部阶段与重试，阶段耗时另记 |
| 评测入口 | 复用执行器，输出原测试用例 ID、策略和错误分类，不另建平行测试集 |

中间产物使用独立的解析策略，仍只从供应商正文通道读取，继续拒绝协议错误、空输出和明确截断。最终正文才应用现有场景正文检查。提取、成文和评测调用不得混用字段或绕过输出保护。

## 9 评测与验收

### 9.1 复用已有测试集

保留现有样本和用例 ID，补充实际长度、场景、已知错误类型等标签。公开合成样本可进仓库，已有私有样本保持原存储边界。没有真实音频的样本只评价文本整理，不能推断语音识别准确率。

先比较当前单次处理和单次受控思考，再对失败集中或提升不足的场景比较两阶段处理。使用相同模型版本、输入、场景规则及服务端点，重复运行已知不稳定样本，记录原始结果与超时、截断等失败。

同时报告两种比较：相同费用或时间预算下的表现；各策略采用合理生产预算后的质量与成本。不能让深入策略获得更多预算后，将全部提升归因于流程设计。

| 维度 | 评价内容 |
| --- | --- |
| 信息完整 | 原文独有的事实、要求、条件、例外是否保留 |
| 原意保真 | 数字、人名、关系、否定和确定程度是否被改动 |
| 场景效果 | 会议分类准确；分享叙述自然；指令约束清晰完整 |
| 完整返回 | 正常完成、空正文、截断、超时和回退分别计数 |
| 使用成本 | 总耗时及 P50/P95、调用次数、实际 token 使用或可用费用数据 |
| 用户可用性 | 原有评分方式下的直接使用程度和必要返工 |

不以输出更长、标题更多、与参考答案逐字一致作为通用质量指标。不把原文回退算作 AI 整理成功；不可观测的费用或模型用量标为未知，不估作零。

### 9.2 自动策略启用条件

某个“场景＋长度区间＋模型能力配置”只有满足以下条件才启用自动深入：目标错误确实减少；已知高风险用例无新增确定的误改；完整返回率没有明显退化；耗时与成本在事先约定的预算内。样本少或结果波动大时继续保留手动深入，不用一次成功替代稳定性证据。

阈值和允许的质量、耗时差异在看到基线后确定，并在候选策略比较前固定。验收报告列出样本量及不确定性，不承诺一次测试实现百分之百准确。

### 9.3 功能验收矩阵

| 情况 | 期望行为 |
| --- | --- |
| 原样转写加原语言，无论长度 | 不调用 AI，保留可复制原文 |
| 翻译或自定义问答 | 不误用会议提取或原文逐项一致限制 |
| 模型不支持开关或始终思考 | 参数合法，界面如实说明实际方式 |
| 两阶段第一阶段失败或剩余时间不足 | 不继续提交无意义请求，保留原文并显示原因 |
| 截断、空正文、思考或协议字段混入 | 不交付为成功正文 |
| 识别已结束，AI 失败或被取消 | 原文仍可找回，取消不粘贴 |
| 空录音或录音阶段取消 | 上一次记录仍可找回 |
| 找回时修改原文 | 原始转录保持不变，新尝试绑定编辑稿修订号 |
| 重处理取消后响应迟到 | 不写入结果、不覆盖新输入、不粘贴 |
| 删除连接或更换服务 | 明确选择有效配置后才能重新提交，不静默换服务 |
| 关闭保存或清除记录 | 取消相关重处理并清除内容，迟到响应无法恢复 |
| 退出再打开应用 | 无历史正文，界面解释只保留当前运行期 |
| 粘贴失败、缺少辅助功能权限 | 找回及复制仍可使用 |
| 新录音抢占重处理 | 重处理停止，新录音正常进行，记录不串写 |
| 内存上限、超长输入 | 不静默裁剪原文或把残缺结果标为完整 |

自动化覆盖策略选择、配置迁移、模型参数、阶段预算、状态竞争和保留规则。人工验收覆盖实际录音、找回窗口、编辑复制、权限缺失、不同应用粘贴、键盘操作和 VoiceOver。离线模拟响应通过不能代替真实模型质量和设备交互验收。

## 10 实施顺序与回退

| 阶段 | 交付内容 | 完成条件 |
| --- | --- | --- |
| A 原文与找回 | 识别结果分离、最近一次内存记录、查看与复制、原文编辑、按原方式重新整理、取消保护 | 不改变现有整理策略，核心找回交互及竞争状态验收通过 |
| B 共用执行器与手动深入 | 从现有路径抽出计划和执行器，快速与深入选项、模型预算适配、迁移；评测接入同一路径 | 现有行为回归通过，可用已有长文本样本比较单次策略 |
| C 按场景自动选择 | 根据评测确定长度阈值，逐场景启用自动思考或保留快速 | 每个启用组合有明确的质量与耗时证据 |
| D 场景分阶段处理 | 先会议记录和 AI 指令，再内容分享；增加来源关联及中间产物校验 | 两阶段优于可比单次策略，且无新增关键事实误改 |
| E 超长分段 | 仅在完整上下文方案不足时实现语义分段和全局整合 | 跨段修正、分歧和约束覆盖得到验证 |

A 可独立交付，先解决重新录音的负担；B 到 D 共用基础设施，但各自独立验证，不需要一次上线全部改动。第一版深入按钮在 B 完成后出现；A 阶段不展示尚不可用的能力。

每个场景策略带版本和启用标志；允许独立关闭自动深入或两阶段，回退到既有单次处理，保留找回功能。配置读取未知策略时使用兼容流程，不修改用户提示词。源码、测试和文档先提交为可审查变更，安装及发布按独立交付步骤验证。

## 11 首版建议与后续决策

建议首版确定为：最近一次输入保存在内存、重处理默认不自动粘贴、不自动换模型、原样转写保持直接输出、普通文本维持单次处理、深入策略从手动使用和现有测试集验证开始。

自动长度阈值、深入等待预算和哪些场景真正需要两阶段，由现有测试结果确定。跨重启保存、音频重新识别和长期历史管理不作为首版依赖；若后来需要，可以在同一输入记录与尝试模型上扩展。

现有证据仅用于定位问题：[2026 年 8 月思考对照](../archive/evaluations/SPOKEN_LATENCY_OPTIMIZATION_2026-08-25.md)显示预算不足可能导致正文不完整；[后处理说明](../ai-postprocessing.md)记录了后续预算与失败回退修复。旧对照不能替代当前模型及真实长文本样本的验证，也不能将所有整理不足归因于模型上限。
