# Spoken 使用统计与监控改版计划

日期：2026-09-11。状态：待评审，尚未开发或启用客户端上报。

当前核对基线为客户端 2.1.1，官网发布配置为 2.1.1 / 218.1。建议将本轮作为 2.2.0 功能版本，最终版本号在发布时确定。

本计划负责改版范围、用户交互、交付顺序和验收；具体指标、接口及存储设计见[技术与指标附录](product-analytics-plan.md)，埋点字段见[事件字典](product-analytics-events.csv)。实施时三份文件一并维护。

## 1. 目标与关键决策

让产品负责人能够持续回答四个问题：

1. 有多少人访问网站、点击下载、发起下载请求，后续有多少安装开始使用？
2. 每天、每周、每月有多少活跃安装，用户是否持续回来？
3. 一份安装使用了多少次语音输入，使用频率、模式和处理时长如何？
4. 录音、识别、AI 和交付哪个环节影响使用，是否因版本更新而退化？

| 决策类型 | 内容 |
| --- | --- |
| 已明确需求 | 统计下载及后续活跃，统计单用户对话数量；形成完整改版方案 |
| 推荐首版方向 | 无账号；随机安装标识；可选统计默认关闭；不上传语音和正文；网站、客户端分别采集，统一看板展示 |
| 推荐实现 | 保留现有 Umami；新增采集 API、PostgreSQL、Metabase；客户端使用异步本地队列 |
| 需在上线前确定 | 统计同意方式、服务部署地区与费用上限、是否增加用户主动的下载归因 |

**“用户”首版按参与统计的安装标识近似；“对话”按一次被接受的语音输入任务计算。** 同一人使用两台 Mac 通常算两份安装；原样转写也算一次任务；AI 内部重试不算新对话。看板使用“活跃安装数”和“语音输入次数”，并展示口径说明。

可选统计只覆盖主动参与且成功上报的安装，不能代表未升级、拒绝统计和长期离线用户。不会恢复改版前的全量使用历史。重新开启或重置会创建新统计身份，因此“首次观测”可能包含同一设备的新周期，不能直接称为净新增安装；本地可确认的已有安装仍标为 existing。

## 2. 改版范围

| 模块 | P0：本轮交付 | P1：后续按需要追加 |
| --- | --- | --- |
| 客户端 | 安装身份、统计同意、任务及阶段事件、离线队列、历史删除；新增“数据与隐私”设置 | 配置与权限事件、每次模型请求尝试、更多诊断维度 |
| 产品网站 | 保留访问和下载点击；增加下载请求入口、直接下载备用入口、数据说明 | 具备条件时增加完整传输估计；用户主动关联下载来源 |
| 采集服务 | 安装登记、批量接收、鉴权、去重、删除、环境隔离、汇总任务 | 随规模优化查询与存储 |
| 数据看板 | 获取与激活、活跃与使用深度、单安装详情、质量与数据健康四张基础看板 | 高级留存分群、请求尝试分析、更多版本对比 |
| 监控 | 采集可用性、入库失败、汇总新鲜度、资源用量监控 | AI 回退、粘贴退化、性能和活跃波动告警，待基线充分后启用 |

P0 包含 D1/D7/D30 留存的查询和展示能力。D30 真实结果需上线后等待 cohort 成熟，不以等待 30 天作为软件发布条件。

本轮不新增账号、云同步、语音历史云存储、会话回放或自动更新系统；不重做模式、模型连接和录音浮窗。统计展示集中在设置页与管理看板，不增加录音流程步骤。

## 3. 客户端产品改版

### 3.1 首次说明与选择

新增一次可跳过的统计说明卡，在用户主动打开菜单面板或设置时呈现。升级后适用同样逻辑；录音、识别、AI 处理及粘贴期间不弹窗，不抢输入焦点。用户选择后不重复催促，后续通过设置修改。

建议文案：

> 分享使用统计，帮助改进 Spoken。仅发送使用次数、模式类型、处理结果和耗时等数据，不发送录音、输入或输出正文、Prompt、个人背景及密钥。可随时关闭或删除已发送的历史统计。

操作为“开启使用统计”“暂不开启”“查看数据说明”。默认未开启，拒绝不影响任何语音功能。“查看数据说明”优先展示应用内说明，避免用户尚未选择时因自动打开网页产生额外统计。

不收集拒绝次数或未同意用户的启动行为，因此首版无法完整计算同意率；看板须说明这一覆盖范围。

### 3.2 设置页增加“数据与隐私”

保留现有“模式与提示词 / AI 模型 / 语音识别 / 个人背景”，新增第五项“数据与隐私”。不将统计开关藏入模型或语音设置。

| 区域 | 内容与交互 |
| --- | --- |
| 使用统计 | 开关、当前状态、简短用途说明；开启或关闭立即生效，不等待其他设置的“保存” |
| 收集范围 | 展示允许的事件和数值类别，明确不收集的内容；提供完整数据说明 |
| 上报状态 | 未开启、等待联网、正常、暂时不可用；显示最后一次服务端确认接收时间，避免将“已入队”显示为“已上报” |
| 统计标识 | 显示可复制的安装标识及本周期开始时间；只用于用户查询，不显示上传或删除凭证 |
| 历史数据 | “删除历史并重置统计标识”；说明将停止统计、清空本地队列并申请删除服务器历史 |

开关与删除操作提供键盘访问、VoiceOver 标签、深浅色状态反馈。错误文字说明下一步，不以颜色作为唯一提示。统计服务异常仅在该页显示，不占用录音的错误提示。

### 3.3 同意、关闭和删除规则

| 操作 / 状态 | 客户端行为 | 界面反馈 |
| --- | --- | --- |
| 从未开启 | 不登记安装，不产生待报行为队列，不上传客户端事件 | 未开启 |
| 主动开启 | 创建本周期身份与凭证；从此刻起记录，网络不可用时先保存在受限队列 | 已开启 / 等待联网 |
| 关闭 | 立即停止新事件，取消在途请求，清空待报队列；已经被服务器接收的数据按保留期处理 | 已关闭；可另行删除已发送历史 |
| 重新开启 | 创建新同意周期和身份；不补报关闭期间数据，不在分析中自动关联旧身份 | 已开启，展示新的统计起点 |
| 删除历史并重置 | 先关闭统计并清队列，再删除本机持有凭证所对应的当前及旧周期历史；服务端撤销旧写入权限 | 删除中；离线时显示“待联网完成” |
| 删除确认完成 | 清除已完成删除身份的本地凭证；保持关闭，下次主动开启才创建新身份 | 历史已删除，统计未开启 |

关闭不等于删除；已经被服务器接收的在途请求无法仅靠客户端取消撤回，需走删除流程。重复删除应安全，迟到事件不能让已删除身份重新出现。

为保证重新开启后仍可删除旧周期数据，本机在 Keychain 中保留旧身份的最小删除凭证清单，仅供用户主动删除，不上传身份间的关联。删除途中不得丢弃尚未完成的凭证；部分成功要区分已完成和待重试。清除本机配置和 Keychain 后，不能承诺仍可通过本机自动定位历史身份；数据说明应写明此边界。

### 3.4 核心流程的埋点改造

新增独立的 `TelemetryClient`、类型化事件及 `TelemetryStore`，不通过上传现有日志实现产品统计。

1. 快捷键触发被应用接受时创建一次 `interaction_id`，记录开始；忙碌期间被忽略的快捷键不计数。
2. 停止录音时沿用现有配置快照，统计仅提取模式类型、供应商枚举等允许字段。不得把包含密钥、Prompt 或背景的快照整体序列化。
3. 记录录音结束、ASR 终态、AI 逻辑终态；原样转写和无需 AI 的路径不伪造 AI 调用。
4. 任务结束统一生成一次终态，区分完成、失败、取消、中断；重复回调、内部重连和重试不重复增加对话。
5. 交付分别记录粘贴命令已发送、仅写入剪贴板、交付失败。当前无法可靠确认目标应用收到文本，不生成虚假的“已验证粘贴”。
6. 崩溃后下次启动恢复未完成任务标记；未再次启动的安装只能记为缺少终态，不能判断已卸载。

任务记录采用原任务 ID 关联阶段事件；只有发生新录音任务才创建新 ID。模型“测试连接”标为独立用途，排除在 DAU、对话数和语音输入的 AI 成功率之外。

### 3.5 队列和失败处理

- 磁盘与网络操作离开主线程；录音、识别、模型处理和粘贴不等待埋点上传结果。
- 建议累计 20 条或有待报数据达 60 秒触发上传；每批不超过 50 条 / 100 KB。停止上传后不通过后台心跳制造活跃。
- 本地队列建议最多 10 MB、10,000 条、7 天，任一条件达到即按优先级淘汰旧事件；容量限制不能影响核心产品。
- 事件 ID 入队时固定，重试复用；服务端事务提交后才确认。支持断网、超时、限流、重复发送和部分批次失败。
- 服务器不可用时指数退避；统计配置损坏、磁盘满或凭证失效时停止受影响的统计功能并提示，不阻止 Spoken 使用。
- 服务端可返回明确的暂停采集状态，客户端停止上传并按约定回查；不下载或执行任意远程代码。暂停期间的队列仍受期限和容量约束。

## 4. 网站、服务端与数据建设

### 4.1 官网改动

1. 保留 Umami 的网页访问和 `download_click`，统一各下载按钮调用，避免单次点击重复触发。
2. 下载主入口改为 `/download`，服务端校验固定版本资源后记录 `download_request` 并跳转到 CDN 安装包。计数失败仍应完成跳转，避免统计服务拖慢下载。
3. 保留旧版本直链和“直接下载安装包”备用入口。跳转服务本身不可用时用户仍有下载路径；直链绕过的统计缺口在看板注明。
4. 更新版本号、发布日期、安装包地址、校验文件与数据说明；页面版本、包内版本和公开校验值发布时一致。
5. 预览站、开发调试、监控探针与生产统计隔离。下载请求排除 HEAD、已知机器人和可识别预取，不声称完全排除所有自动访问。

本期展示“按钮点击量”“下载请求量”“首次观测安装”“首次激活安装”。没有文件传输证据时不显示“下载完成量”；没有用户主动建立跨端关联时不显示用户级下载到安装转化率。

### 4.2 采集与存储

采用现有网站统计＋独立产品采集服务。使用 PostgreSQL 保存事件及汇总结果，Metabase 提供受限访问的管理看板；具体服务托管方式待部署地区和预算确定。

| 交付物 | 必须具备的行为 |
| --- | --- |
| 安装登记接口 | 仅在同意后登记，签发安装专属凭证；不复用用户的模型 Key |
| 事件接收接口 | 类型和字段白名单、大小限制、安装级权限、限流、版本兼容、幂等入库、逐事件确认 |
| 历史删除接口 | 校验删除凭证；删除原始、事实、按日、累计和关联资料；撤销旧写入权限；返回真实处理状态 |
| 定时汇总任务 | 生成任务事实、安装日活和累计指标；接受乱序与补传；重算最近窗口，防止重复累计 |
| 数据管理 | production / staging / test 隔离；备份、恢复演练、定期清理、删除清单重放 |
| 访问管理 | 服务凭证与管理权限分开；看板使用只读受限视图；原始明细仅授权人员可查 |

数据库至少覆盖安装、原始事件、任务事实、安装按日汇总、安装累计、网站窗口汇总、下载请求。P1 增加模型请求尝试明细时沿用任务关联。

网站与客户端通过统一时间窗口、版本和渠道维度并列展示；首版不建立浏览器 ID 与安装 ID 的身份映射。开源客户端凭证并不能阻止所有伪造事件，需通过限流、字段校验和异常分布监控降低污染。

### 4.3 数据与内容边界

只收集随机标识、受控枚举及数值，例如版本、模式类型、供应商、录音时长、字数、处理耗时、结果与错误码。

不上传音频、转录、AI 正文或思考过程、Prompt、个人背景、模型密钥、Base URL、自定义模式名称、连接名称、窗口信息、剪贴板正文和具体目标应用身份。未知手填模型归为 `custom_model`，不借模型名称字段发送自由文本。

原始事件与任务明细建议保留 90 天，按日汇总 400 天；安装累计在持续参与期间保留，连续 400 天无活动后清除可关联资料。备份最长建议 30 天，恢复时重放删除清单。所有这些数值均为上线配置建议，需要与数据说明一致。

网络接入必然会让接收端看到来源地址；产品分析表不保存 IP，不用 IP 或设备指纹匹配用户。网关安全日志单独限制字段、访问和保留时间。

## 5. 看板与指标

### 5.1 四张 P0 看板

| 看板 | 核心内容 | 支持的产品判断 |
| --- | --- | --- |
| 获取与激活 | 网站 PV/UV、下载点击及窗口去重访客、下载请求、首次观测安装、首次激活、成熟 cohort 的 7 日激活率 | 区分官网触达与产品开始使用；分清老用户升级首次被观测和新安装 |
| 活跃与使用深度 | DAU/WAU/MAU、语音输入总数、人均/中位数/P90、活跃天数、录音量、模式分布、D1/D7/D30 留存 | 判断是否持续使用、使用深度变化和主要使用场景 |
| 单安装详情 | 安装标识、首次观测/激活/最近活跃、今日/7 日/30 日/累计输入数、完成与失败、模式及耗时汇总 | 回答“一份安装用了几次”；在用户提供标识后定位体验问题 |
| 质量与数据健康 | ASR/AI 成功与回退、取消/中断/缺少终态、交付方式、阶段耗时、输出防护拒绝、上报延迟、入库错误、汇总更新时间 | 判断产品问题还是数据采集问题，检查版本变化 |

单安装页面只显示受控统计，不提供语音内容回放。累计注明参与统计起点；明细注明可查询范围。小样本、无数据和零值分别展示，不填造结果。

### 5.2 必须固定的口径

- **DAU**：当天有被接受的语音输入任务的去重安装数。仅打开应用、开机常驻、切换模式或测试连接不计核心活跃。
- **MAU**：最近 30 个自然日含当天的去重活跃安装；自然月活跃另列，不能相加日活得到月活。
- **对话数**：去重任务 ID 的数量，包含原样转写；同时分别列完成、失败、取消、中断和缺少终态。
- **激活**：首次完成并产生可交付结果；保留原转录的成功回退可计激活，但不等于验证目标输入框收到文本。
- **AI 回退率**：实际进入 AI 且已结束的任务中，由 AI 错误导致保留原转录的占比；不将没有进入 AI 的配置失败放入同一分母。
- **留存**：首次激活日为 D0，第 N 个自然日有任务才计 DN 留存，只使用已成熟 cohort；未成熟标为“待观察”。
- **输出防护**：`unsafe_output` 表示被防护拒绝的输出，不能直接等同实际泄露；`cleaned` 可能只是普通包装清理，不能称为思考泄露数量。
- **时间**：事件按 UTC 存储，看板按 Asia/Shanghai 切日；任务归开始日期，离线补传不计成补传当天的新使用。

看板建议每 5–15 分钟更新，显示最后更新时间和补传修正说明。DAU 等数值随迟到、删除和修正可能变化。日常业务判断先看数据新鲜度，再解释增长或流失。

### 5.3 监控安排

P0 配置采集服务探针、入库失败、汇总任务失败、磁盘及数据库容量监控；探针使用隔离环境/身份，不进入正式人数。明确告警接收人与处理责任后才配置外部通知。

P1 在积累至少 7–14 天有效基线后，启用 AI 回退、输出防护异常、剪贴板回退、处理耗时和活跃下降告警。使用最小样本量、冷却时间和恢复通知；低量阶段优先人工核查，避免每次正常失败都报警。初始阈值见技术附录。

## 6. 实施顺序、工作量与交付物

### 6.1 阶段安排

| 阶段 | 主要工作 | 交付及进入下一阶段的条件 |
| --- | --- | --- |
| 0. 确认范围 | 确认同意方式、指标口径、部署地区、预算及责任人；定稿数据说明和事件版本 | P0 范围及口径冻结，可并行准备本地代码骨架和测试夹具 |
| 1. 数据基础 | 接口契约、身份与凭证、数据库、幂等及删除；搭建 staging | 合成事件完成接收、去重、汇总与删除闭环 |
| 2. 客户端与网站 | 设置页、统计状态、核心流程事件、队列；下载跳转与备用入口 | 离线回归、本地构建和各模块测试通过；不开启生产采集 |
| 3. 看板与联调 | 四张看板、留存查询、采集监控；固定数据集核算；抓包检查 | 全链路数值正确，敏感内容未进入请求/日志/存储 |
| 4. 小范围试用 | 内部实机，再邀请明确同意的外部试用；验证升级、录音和真实粘贴 | 阻断问题清零，数据误差可解释，完成发布清单 |
| 5. 公开发布 | 发布客户端、官网说明、安装包和校验文件；观察错误与数据健康 | 记录首版观测基线和未解决限制，再确定 P1 排期 |

### 6.2 P0 工作量估算

| 工作包 | 估算 | 主要责任 |
| --- | --- | --- |
| 客户端设置、事件、身份和队列 | 3–5 人日 | macOS 开发 |
| 采集服务、存储、去重与删除 | 2–4 人日 | 后端开发 |
| 官网入口、指标查询、四张看板 | 2–3 人日 | Web / 数据开发 |
| 端到端、隐私、升级和发布验收 | 2–3 人日 | 测试，开发配合 |
| **总计** | **9–15 人日** | 产品负责人确认口径与上线范围 |

这是基于当前代码和采用现成看板工具的初步估算，包含必要开发自测和联调，不是工期承诺。单人串行约 2–3 个工作周；多人可并行，但仍受接口、同意流程和端到端验收依赖。资源采购、域名配置、签名发布准备和试用观察时间另计，不压缩成开发人日。

建议内部 3–5 份安装观察 1–2 天，再由 10–20 份自愿试用安装观察 3–7 天。这些是试用规模建议，不是必须招募的业务指标；不足以验证低频问题时延长观察。

实施产出包括：客户端与网站改动、服务端与数据库迁移、带版本的事件字典、合成测试数据及指标预期、四张看板、数据说明、监控配置、发布与回退操作说明、验收记录。代码评审后按授权提交和发布，不把私有配置、密钥、用户数据或安装产物提交到公共源码仓库。

## 7. 验收与测试方案

不以“事件能收到”作为完成标准。需同时通过产品流程、数据正确性、隐私选择和性能四类验收。

| 编号 | 验收场景 | 通过标准 |
| --- | --- | --- |
| A01 | 同一安装一天录音 3 次，其中一次 AI 内部重试 | DAU=1、任务数=3；重试不增加任务数 |
| A02 | 两份安装跨天、跨月、跨午夜，另有常驻与连接测试 | 固定夹具算出准确 DAU/WAU/MAU；任务按开始日归属；常驻/测试不计活跃 |
| A03 | 原样转写、各预设、自定义、AI 回退、ASR 失败、取消 | 每次接受的任务恰有一个身份，已结束任务的终态唯一，各分母一致 |
| A04 | 录音中切换模式，停止后修改模型/Prompt/语言 | 归因使用本次冻结配置；不上报 Prompt 等内容 |
| A05 | 重复终态、重复批次、乱序、ACK 丢失、断网补传 | 汇总不重复增长，补传回到原日期；部分失败不会误删未接收事件 |
| A06 | 进程中断、恢复、长期不重启、终态迟到 | 可恢复中断和缺少终态分别统计；不推断卸载，不重复算新增任务 |
| A07 | 默认关闭、主动开启、关闭、重新开启 | 抓包验证无未同意行为上报；无关闭期间补传；新周期身份不自动拼接旧记录 |
| A08 | 在线/离线删除、部分身份删除失败、删除后迟到事件 | 删除状态真实可重试；旧周期可删除；清除事实/累计/明细，旧凭证不可重新写入 |
| A09 | 检查请求、日志、数据库和备份 | 没有音频、正文、思考、Prompt、背景、密钥、地址和窗口内容；自由文本属性被拒绝 |
| A10 | 采集接口断开、限流、慢响应、队列满、数据库异常 | 录音与交付继续工作；队列有界，重试有退避，故障不引发持续联网 |
| A11 | 同机埋点开/关各至少 100 次合成流程 | 核心流程不等待统计磁盘/网络；单次入队调用 P95 目标 <2 ms；记录 CPU/内存和耗时对照，无可感知退化 |
| A12 | 官网点击、有效 GET、HEAD、预取、重复请求、直链与跳转失败 | 各统计名与观测一致；不将点击或请求当成安装/下载完成；备用下载可用 |
| A13 | 留存 cohort 未成熟、成熟、补传、历史删除 | 未成熟不显示为 0；固定样本的 D1/D7/D30 与预期一致；删除及补传能修正结果 |
| A14 | 深浅色、键盘、VoiceOver、小屏幕及未保存设置 | 统计操作可访问且状态明确；不干扰已有草稿保存；录音过程中不弹说明卡或抢焦点 |
| A15 | 从当前正式版升级，实际录音并交付到编辑器、浏览器输入框和聊天输入框 | 模式、连接及密钥仍有效；权限状态可用；人工确认真实粘贴，同时事件只报告可观测结果 |
| A16 | 生产/测试环境、服务端回退、备份恢复、监控告警 | 测试不进入生产指标；旧客户端仍兼容；已删除数据不因恢复而重新可查询；告警发送到指定人员 |

测试分三层：客户端离线单测覆盖状态机、队列、同意及字段过滤；服务端集成测试覆盖鉴权、幂等、事务、删除和指标查询；实机冒烟覆盖网站下载、升级、录音、处理与跨应用粘贴。沿用项目实施时的离线回归基线，但离线通过不能替代实机验收。

AI 网络集成优先使用模拟服务及合成文本；只有另行明确授权时才调用真实模型。私有语音样本不进入数据平台或公开测试仓库。本次文档交付不代表这些实现测试已经执行。

## 8. 发布、回退与运营使用

### 8.1 发布条件

- P0 功能、上述验收和本地构建通过；无未解决的核心录音/粘贴回归、敏感字段泄露或重复计数问题。
- 数据说明、同意界面、保留期和服务部署配置一致；删除、监控、备份恢复有人负责。
- 使用内部或试用专用下载链接做小范围发布。当前检视未发现自动更新接入，不假设已有自动灰度能力。
- 公共发布时核对源码版本、包内版本、官网版本、安装包校验与签名状态；实际验证升级后的辅助功能和麦克风权限。
- 网站主下载、备用直链与旧版本归档均可用；分析页面不公开单安装明细。

### 8.2 回退策略

统计服务异常先暂停采集或关闭相关开关，保留 Spoken 核心功能。客户端必须识别暂停/退避响应，避免单纯断开接口后持续重试。

客户端出现核心回归时，将官网推荐下载恢复到经过验证的前一版本，提供明确的回退安装说明；已分发版本无法靠更换网页自动撤回。保留原版本资源，不覆盖同名安装包。

数据库变更首版采用兼容性扩展；回退服务时仍能处理已分发客户端的事件版本。暂停后的队列按原保留期限处置，不在恢复时无限补传。恢复数据库前执行删除清单，避免已删除历史复活。

### 8.3 上线后的使用节奏

首周每天检查采集可用性、数据延迟、版本分布与任务终态缺失，再看使用量；发现统计异常优先修正数据链路。

从第二周起每周查看新增可观测安装、激活、活跃、输入深度、成熟留存及主要失败环节。单安装详情用于用户主动反馈后的定位，不读取或重建对话内容。

达到相应观察窗口后再解释 D7/D30；关闭统计、版本覆盖变化会影响留存判断。P1 根据真实问题选取，先补能解释当前问题的事件，不默认收集全部可获取信息。

## 9. 开发与上线前待定项

| 待定项 | 建议 | 最晚决定节点 |
| --- | --- | --- |
| 统计同意方式 | 默认关闭，用户主动开启，可随时关闭和删除 | 客户端交互定稿前 |
| 部署地区、服务方、月度费用上限 | 选择能稳定服务目标用户的区域；保留现有 Umami，其他按小规模起步，实施前核价 | 开通生产资源前 |
| 下载到安装的个人级归因 | P0 不做；先分别观测下载与激活，必要时 P1 增加用户主动关联 | P0 范围冻结前 |
| 数据访问和告警责任人 | 指定产品负责人和技术维护人；管理入口限制访问 | 真实试用数据接入前 |

前两项会直接影响客户端流程和资源配置，需要确定后再部署正式采集。其余本地开发、接口设计和合成测试可在建议范围下准备，不需要先开通付费服务。
