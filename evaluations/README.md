# Spoken 评测体系

本目录固化 Spoken 提示词与模型改版的标准评测体系：**一套标准评测集 + 一套统一评估方式 + 定期迭代政策**。
任何提示词或模型改版的效果结论，必须以本体系跑出的前后对照为准。

## 1. 标准评测集

**当前版本：v1 = `evaluations/scene_targeted_samples_2026-09-30.json`（124 题）**

- 覆盖全部 7 个场景模式：`raw_transcript`（R1–R10）、`casual_chat`（C1–C19）、`work_message`（W1–W19）、`formal_document`（F1–F19）、`meeting_notes`（M1–M19）、`content_share`（P1–P19）、`ai_instruction`（A1–A19）。
- 长度分布：短 28 / 中 75 / 长 21，短中句为主，模拟真实语音输入。
- 每题字段：`id`、`title`、`expected_scene`、`target_mode_id`、`length_class`、`focus`（考点，评审的首要依据）、`input`。
- 题目围绕"模型易错点"设计：同音术语还原、隐性意向词保真、改口归并、否定保留、数字归属、会议归类边界、不编造、不补写、短输入不过度整理。

历史集（仅存档，不再作为标准）：`scene_depth_samples_2026-08-24.json`、`scene_targeted_samples_2026-09-29.json`、`short_input_samples_2026-09-30.json`。

## 2. 统一评估方式

### 2.1 运行（标准化一步命令）

```bash
scripts/run_standard_evaluation.sh            # 默认：当前 App 生效连接，输出到 evaluations/results_<日期>_<模型>.json
SPOKEN_EVAL_MODEL=qwen3.8-flash SPOKEN_EVAL_THINKING_MODE=off scripts/run_standard_evaluation.sh   # 固定模型对照
```

固定参数（wrapper 已内置，不要改）：`SPOKEN_EVAL_MATCHED_ONLY=1`（每题只跑其 `target_mode_id`，124 次请求）、标准评测集 v1。
结果文件命名：`results_<YYYY-MM-DD>_<model>_<thinking>_prompt-v<N>.json`，提交入库归档，命名中的 prompt 版本对应 `ModeStore.swift` 的配置版本。

### 2.2 评审（rubric）

逐题对照该题 `focus` 与对应场景契约（`scripts/run_prompt_evaluation.sh` 的 `BASE_RULES` + `task_instruction` 分支），给出四级结论：

| 结论 | 定义 |
|---|---|
| 通过 | 符合考点与场景契约 |
| 轻微 | 不丢信息、不编造，但语气/分段/措辞/数字写法与考点有偏差 |
| 存疑 | 行为对错两可，需人工裁决并记录裁决理由 |
| 未通过 | 触碰红线：编造原文没有的事实/数字/观点/待办/结论；不确定表述被删除或升级为确定；否定写反；数字或对象归属串错；高置信术语未还原或含义不明被擅改；短输入过度扩写；AI 指令执行了任务或保留 Spoken 称呼；会议记录建议/设想入待办或结论、进展类事实丢失；内容分享补感悟/号召/占位符/挽回性表述；流畅转写场景化改写/概括/重组/丢信息 |

评审 prompt 模板见 `evaluations/review_prompt.md`，逐字复用，保证各轮评审口径一致。可按模式并行评审（每模式一个评审实例）。

### 2.3 前后对照方法

1. **行为级比对优先于结论计数**：逐题 diff 两版输出原文。结论计数受评审宽严漂移影响（±2 题内视为噪声），行为变化才是硬证据。
2. **关键案例人工复核**：所有"未通过"与上轮曾未通过的题，必须人工看输出原文定性：修复 / 同行为从严 / 行为劣化 / 不稳定翻转。
3. **稳定性要求**：一项"修复"需连续 ≥2 轮复测保持，才算稳定修复；单轮命中按不稳定处理。
4. **落地标准**：旧版系统性问题清零或仅剩模型层限制 + 无新增系统性回归，才允许落地新提示词。
5. **迭代纪律**：单题修补不超过两轮，警惕否定示例反向提示（反例概括表述、不点名具体措辞）；优先写"允许的正向形态"而非只写禁令。

## 3. 评测集迭代政策（定期更新）

评测集**必须**随以下事件迭代，否则对照价值会衰减：

1. **触发时机**：
   - 每次提示词或模型改版后暴露出新错误模式（将失败案例提炼为新题）；
   - 真实使用中发现的翻车案例（脱敏后录入）；
   - 新增/修改场景模式时（每模式不少于 10 题）。
2. **新增规则**：
   - ID 顺延现有编号（如 C20、R11），不复用、不删除旧题——旧题是回归防线；
   - 每题必须写清 `focus` 考点；优先收录模型易错句式与真实口语句式；短中句为主；
   - 题目入集前需在当前版本上跑一遍确认其区分度（能稳定通过或稳定暴露问题的才保留，纯随机翻转的题标注"不稳定"）。
3. **版本化**：题目有实质增删时生成新的日期文件并升为 v2、v3……，本 README 更新"当前版本"指针；旧文件原地保留不改动，保证历史报告可复现。
4. **责任人**：每次提示词改版的提交中，如需新题，评测集更新与提示词修改同提交入库。
